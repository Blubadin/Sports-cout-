## 2. แผนแก้ (อ้างอิงแนวคิดจากโปรเจกต์ที่พักไว้ — ดู §4)

ลำดับงาน — ทำทีละข้อ พร้อมวัดซ้ำด้วยวิดีโอเดียวกัน:

1. **A. แยก "ติดตามคน" ออกจาก "ระบุตัวตน"** (สำคัญที่สุด, ตรงกับหลัก V03 ของ SportScout v2: *ไม่บังคับ identity ให้ครบ roster*)
   - ให้กรอบของคนที่ถูกตรวจจับ/ต่อเนื่องบนสนามแสดงได้ แม้ identity ยังกำกวม โดยติดป้าย `UNKNOWN`/`P?` + `trackId` แทนการหายทั้งกรอบ
   - เหตุผลที่ผู้ใช้เห็นว่า "หลุด" ส่วนใหญ่คือกรอบหายตอนระบบลังเลเรื่อง identity ไม่ใช่เพราะมองไม่เห็นตัวคน
   - ต้องคง invariants: `trackId` ≠ `playerId`; ห้ามเดา identity; ไม่นับ UNKNOWN เข้าระยะทาง/สถิติรายคน
2. **B. Offline tracklet stitching ทั้งคลิป** (แนวคิดจาก badminton-ai-analyzer; เขียนใหม่ ไม่คัดลอกโค้ด)
   - เก็บ tracklet ดิบจาก ByteTrack → หั่น tracklet ที่ตำแหน่งกระโดดผิดปกติ/สีเสื้อเปลี่ยน → ต่อเข้า 4 ช่องผู้เล่นพร้อมกันทั้งคลิปด้วยข้อจำกัด: ห้ามซ้อนเวลา, ระยะต้องเป็นไปได้ตามช่องว่างเวลา, ฝั่งตาข่าย, สีเสื้อ, และจุดยึดจาก seed ตอนต้นคลิป
   - ผลคือไม่ต้องรอยืนยัน 3 เฟรมทุกครั้งและแก้ย้อนหลังได้ (ใช้ context อนาคต) — ผลของข้อ 5
   - ผลลัพธ์ต้องติด provenance `OFFLINE_STITCH` แยกจากผลออนไลน์ ห้ามนับเป็น "สังเกตจริงเฟรมนั้น" ในสถิติที่ต้องเฟรมสด
3. **C. ปรับตัวตรวจจับ**: ทดลองอินพุต 1280 (ทำอยู่) → ถ้าไม่พอ ทดสอบโมเดลใหญ่ขึ้น; **ต้องเลือกโมเดลที่ license แจกจ่ายได้** (ultralytics/YOLOv8 เป็น AGPL — แผน SportScout v2 T81 ระบุให้เทียบ RF-DETR / D-FINE / RT-DETRv2 / YOLOX ผ่าน ONNX) ดาวน์โหลดน้ำหนักใหม่ต้องได้รับอนุมัติและบันทึก license/hash ก่อน
4. **D. ลด pose stride เป็น 1** เมื่อ GPU ไหว เพื่อไม่ต้องใช้ pose ซ้ำ (ระยะทาง/ตำแหน่งเท้าจากข้อเท้าจริงทุกเฟรม) — วัดต้นทุนเวลา
5. **E. วัดผลให้จริง** (ตาม V02 T85): ID switches, wrong-player seconds/hour, unknown coverage, IDF1/HOTA — **ต้องมี ground truth ที่คนกำกับก่อน** จึงอ้างความแม่นยำได้ ปัจจุบันมีแค่ proxy (coverage, side consistency)

## 3. ผลทดลองอินพุตตัวตรวจจับ 1280 (session_c2d6950d)

วิดีโอและค่าอื่นเหมือนรอบ 640 ทุกอย่าง (รันเดี่ยว 1 ครั้งต่อค่า ไม่มีการทำซ้ำเพื่อวัดความแปรปรวน):

| | 640 | 1280 |
|---|---|---|
| เฟรมที่ผู้เล่นหายและไม่มี detection ว่างเหลือเลย | 409 | **180** |
| coverage P1 / P2 / P3 / P4 | 0.91 / 0.88 / 0.95 / 0.95 | 0.92 / 0.87 / 0.92 / 0.96 |
| เฟรมที่เห็นครบ 4 คน | 1502 | 1492 |
| ระยะทางรวม P1 / P2 / P3 / P4 (m) | 41.0 / 19.6 / 56.2 / 21.3 | 20.3 / 45.0 / 26.3 / 32.8 |

ข้อสรุป:
- 1280 ลดช่วงที่ตัวตรวจจับมองไม่เห็นคนลงกว่าครึ่ง (409 → 180 เฟรม) แต่ **coverage รวมไม่ขยับ** → คอขวดที่เหลือคือชั้น identity/association (สาเหตุ 5) ไม่ใช่ตัวตรวจจับ
- **ระยะทางรายคนไม่นิ่ง**: ค่าสลับกันมากระหว่างสองรอบ (เช่น P3 56 → 26 m, P2 20 → 45 m) แต่ผลรวมรายทีมใกล้เคียงกัน (ทีมไกล 60.6 vs 65.3, ทีมใกล้ 77.5 vs 59.1)
  แสดงว่ายังมีการสลับป้าย **ระหว่างเพื่อนร่วมทีม** ซึ่งตัวชี้วัดฝั่งตาข่ายตรวจไม่เจอ → **ห้ามนำระยะทาง/heatmap รายคนไปอ้างเป็นสถิติจริงจนกว่าจะแก้ข้อ A/B และมี GT**
- การรันเสียเวลาเพิ่ม (1280 ช้ากว่า 640) — ยังไม่ได้วัดเวลาอย่างเป็นระบบ
